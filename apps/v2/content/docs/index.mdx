Animate UI animates the primitives your components are built on, not the components themselves. Your shadcn/ui components stay yours: same structure, same styles, same API. Only the import of their primitive changes.

```tsx
import { Accordion as AccordionPrimitive } from 'radix-ui'; // [!code --]
import { Accordion as AccordionPrimitive } from '@animate-ui/react/primitives/radix-ui'; // [!code ++]
```

## Why primitives

shadcn/ui components change often, and come in many styles and bases. Animate UI doesn't copy them: each Animate UI primitive has exactly the API of its library, with Motion inside. Whatever your shadcn/ui configuration, swapping the import is enough, and one command does it for every installed component:

```npm
npx @animate-ui/cli@latest animate all
```

## Motion that feels right

Every primitive follows the same rules: springs and short tweens on a strong ease-out, exits quicker than entrances, transforms and opacity rather than layout, interruptible animations, and nothing on keyboard navigation. Reduced motion is respected everywhere, without any setup.

The motion is restrained on purpose. A menu opened fifty times a day has to feel quick, not impressive: each primitive animates just enough to show where things come from and where they go, then gets out of the way. The balance between motion and the experience of using your app always comes first.

## Libraries

Animate UI supports [Radix UI](https://www.radix-ui.com), [Base UI](https://base-ui.com) and [React Aria](https://react-spectrum.adobe.com/react-aria/), the three bases of shadcn/ui, plus a few primitives of its own.
