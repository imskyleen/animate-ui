## Usage

```vue
<script setup lang="ts">
import {
  SelectContent,
  SelectIcon,
  SelectItem,
  SelectItemIndicator,
  SelectItemText,
  SelectPortal,
  SelectRoot,
  SelectTrigger,
  SelectValue,
  SelectViewport,
} from '@animate-ui/vue/primitives/reka-ui';
</script>

<template>
  <SelectRoot default-value="geist">
    <SelectTrigger aria-label="Font">
      <SelectValue placeholder="Choose a font" />
      <SelectIcon />
    </SelectTrigger>
    <SelectPortal>
      <SelectContent position="popper" :side-offset="4">
        <SelectViewport>
          <SelectItem value="inter">
            <SelectItemText>Inter</SelectItemText>
            <SelectItemIndicator>✓</SelectItemIndicator>
          </SelectItem>
          <SelectItem value="geist">
            <SelectItemText>Geist</SelectItemText>
            <SelectItemIndicator>✓</SelectItemIndicator>
          </SelectItem>
        </SelectViewport>
      </SelectContent>
    </SelectPortal>
  </SelectRoot>
</template>
```

### Check animation

The chosen item's check draws itself while the previous one erases itself. With `animation="pop"` on every item's SelectItemIndicator, the check glides from the previous item to the chosen one instead (a first choice pops it in from half its size):

```vue
<SelectItem value="geist">
  <SelectItemText>Geist</SelectItemText>
  <SelectItemIndicator animation="pop">✓</SelectItemIndicator>
</SelectItem>
```

The same demo with `check-animation="pop"` (its Controls switch it back to `draw`):

<VueComponentPreview
  name="reka-ui/select"
  values={{ checkAnimation: 'pop' }}
  code={false}
/>

To pop every check of your app at once (checkboxes, menus, selects), set `check-animation="pop"` on an [`AnimateUIProvider`](/docs/vue/installation) instead.


## Animation

The motion of Animate UI's React Select:

- **Content** with `position="popper"` fades and scales in from 0.9, from the trigger (`--reka-select-content-transform-origin`), in 220ms (`{ duration: 0.22, ease: [0.215, 0.61, 0.355, 1] }`, a soft ease-out), and closes the same way before it unmounts.
- **SelectValue**: when the choice changes, the old text rises 6px into a 4px blur and fades, while the new one rises 6px into place out of the same blur, in 400ms on a soft ease-out (`{ duration: 0.4, ease: [0.215, 0.61, 0.355, 1] }`), instead of changing in one frame. The trigger keeps its size. When the list is laid over the trigger, the swap waits for it to start fading out, so it's seen.
- With `position="item-aligned"` (reka-ui's default), the list is laid over the trigger with the selected item lined up on the value, so it only fades: there is no side to grow from, and a scale would skew reka-ui's measurement.
- **The highlight**: one surface glides behind the highlighted item on a spring (stiffness 500, damping 40), following the pointer and the arrow keys alike's menu highlight. Moving to another item, it carries on from where it is, at its speed: however fast the pointer or the arrow keys go, there's one highlight on screen. It only fades in (200ms, on CSS's `ease`) when it appears from nothing, and its color changes the same way when the item's highlighted background differs from the previous one's. It glides on the compositor (a Web Animation of `transform`), so a busy main thread, a heavy render for instance, doesn't stall it. When the pointer leaves the list, it stays on the last item. It wears the item's own highlighted background (`focus:bg-accent`, `data-highlighted:bg-accent`…), read from your styles: the item's background is cleared while it's highlighted; its text colors stay.
- **ItemIndicator**: the chosen item's check draws itself like a Checkbox's check (its stroke and opacity in 0.3s on Motion's easeOut, at once) while the previous one erases itself, and the list holds still for 250ms before it closes, so the change is seen nearly done before the list fades out. With `animation="pop"` (or `checkAnimation="pop"` on an `AnimateUIProvider`), the check glides there instead, on the highlight's spring (stiffness 500, damping 40), and the list holds for 150ms, and a first choice pops it in from half its size out of a 2px blur (a spring, stiffness 500, damping 24). The demo's Controls switch between the two. Choosing the item already chosen, and closing any other way (Escape, a click outside), don't wait. Only a change of selection animates the checks: opening the list shows them at rest. reka-ui renders the indicator for the chosen item only: in the animated list, Animate UI renders it on every item (the same `<span aria-hidden>`), so a check can hide itself.
- Reopening while the list is closing picks up from where it is. A closing list is `inert`, so it can't be clicked through.
- After the exit, the closed list goes back to reka-ui, which keeps the items mounted off-screen: the trigger keeps its label, typeahead on the closed trigger and native form submission still work.
- `force-mount` (on `Content` or `Portal`) doesn't keep the closed list mounted: it plays its exit, then leaves, so a closed select never blocks clicks on the page.
- Open from the start (`default-open`), the list plays its entrance on page load.
- Under reduced motion, nothing scales or glides: the list and the checks only fade, and the list doesn't hold; the highlight jumps from item to item and only fades in when it appears.

## API Reference

Every part takes exactly the props of [reka-ui's Select](https://reka-ui.com/docs/components/select#api-reference). Animate UI adds the animation props below.

### SelectRoot, SelectTrigger, SelectValue, SelectIcon, SelectPortal, SelectViewport, SelectItemText, SelectGroup, SelectLabel, SelectSeparator, SelectScrollUpButton, SelectScrollDownButton, SelectArrow

[reka-ui props](https://reka-ui.com/docs/components/select#root) only. They are not animated.

### SelectItem

[reka-ui props](https://reka-ui.com/docs/components/select#item) only. It takes part in the highlight; it needs nothing more.

### SelectContent

[reka-ui props](https://reka-ui.com/docs/components/select#content), plus:
