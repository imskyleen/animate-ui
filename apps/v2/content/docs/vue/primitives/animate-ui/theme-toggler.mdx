## Usage

```vue
<script setup lang="ts">
import { useColorMode } from '@vueuse/core';
import {
  ThemeToggler,
  type ThemeSelection,
} from '@animate-ui/vue/primitives/effects/theme-toggler';

const { store, system } = useColorMode();
</script>

<template>
  <ThemeToggler
    :theme="store as ThemeSelection"
    :resolved-theme="system === 'dark' || store === 'dark' ? 'dark' : 'light'"
    :set-theme="(theme) => (store = theme === 'system' ? 'auto' : theme)"
  >
    <template #default="{ effective, toggleTheme }">
      <button @click="toggleTheme(effective === 'dark' ? 'light' : 'dark')">
        {{ effective === 'dark' ? 'Light mode' : 'Dark mode' }}
      </button>
    </template>
  </ThemeToggler>
</template>
```

During the wipe, the `dark` class is toggled on `<html>`: this matches class-based dark mode (Tailwind's default, VueUse's `useColorMode`).

## Animation

- The new theme is revealed with a clip-path wipe over 700ms with an `ease-in-out`, in `direction` (left to right by default). The old and new pages are snapshots, so nothing re-renders mid-wipe.
- `set-theme` is called once the wipe finishes; `@immediate-change` fires right away.
- Switching to `system` when it resolves to the current theme changes nothing on screen, so there is no wipe.
- Browsers without the View Transitions API swap the theme at once.
- `<AnimateUIProvider :tempo>` paces the wipe.
- Under reduced motion, the theme swaps at once, without the wipe.
- On the server and while hydrating, the render function receives `effective: 'system'` and `resolved: 'light'`, since the theme is only known on the client.
