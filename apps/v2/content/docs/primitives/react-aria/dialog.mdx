## Usage

Import from Animate UI instead of `react-aria-components`: it re-exports all of React Aria, with animated `Modal` and `ModalOverlay`. Everything else stays the same.

```tsx
import {
  Button,
  Dialog,
  DialogTrigger,
  Heading,
  Modal,
  ModalOverlay,
} from '@animate-ui/react/primitives/react-aria';

export function EditProfile() {
  return (
    <DialogTrigger>
      <Button>Edit profile</Button>
      <ModalOverlay isDismissable>
        <Modal>
          <Dialog>
            <Heading slot="title">Edit profile</Heading>
            <Button slot="close">Save</Button>
          </Dialog>
        </Modal>
      </ModalOverlay>
    </DialogTrigger>
  );
}
```

A `Modal` on its own (without a `ModalOverlay`) animates too. `DialogTrigger`, `Dialog` and `Heading` are not animated.

## Sheet

shadcn/ui's Sheet is the same primitive: its `Modal` carries `data-side`, and it then slides in from that edge, fading in, like Animate UI v1's Sheet, instead of tipping in. Add it with `shadcn add sheet`, then animate it with `animate-ui animate sheet`.

## Animation

React Aria has no Animate UI v1 counterpart: the motion is v1's Dialog (Radix UI, Base UI and Headless UI shipped the same one) with a quicker exit and, for the Sheet, v1's Sheet sliding in on a soft ease-out.

- **ModalOverlay** comes in over 400ms on CSS's `ease` (`cubic-bezier(0.25, 0.1, 0.25, 1)`), which starts and lands gently, so the page never changes all at once, on the first frame or on the last, and clears the same way in 250ms once the modal is dismissed. React Aria renders the Modal inside it, where v1's overlay and content were siblings: fading its opacity (or filter) would fade and blur the modal too and cut its exit short. So it fades its own background color and backdrop filter, from transparent to the values its classes set, its blur growing as it's seen (its radius rises slowly at first, where the eye sees most of a blur, so what's seen of it keeps pace with the tint), and the modal moves exactly like v1's content.
- **Modal** tips forward into place, around its center: it starts from `perspective(500px) rotateX(-20deg) scale(0.8)`, transparent and blurred (4px), and comes upright and sharp on a spring (stiffness 150, damping 25), fading in ahead of it (400ms on a soft ease-out), and ahead of the overlay: it's there first, then it settles. Dismissed, it goes back the way it came, at once, quicker and speeding away (0.2s, a steady push from half its average speed to one and a half), out of sight just before the overlay has cleared, then unmounts.
- `from` picks the edge the modal tips from, as in v1: `top` by default (`rotateX(-20deg)`), `bottom` (`rotateX(20deg)`), `left` (`rotateY(20deg)`) or `right` (`rotateY(-20deg)`) (a sheet, with `data-side`, slides from its side instead).
- With `data-side="top" | "right" | "bottom" | "left"` (shadcn/ui's Sheet), the modal slides in from that edge by its own size and fades in, in 0.4s on a soft ease-out (`cubic-bezier(0.215, 0.61, 0.355, 1)`): it answers at once and slows down all the way in. Unlike a drawer it doesn't go past its rest: held against the screen's edge, it would open a gap there. Dismissed, it leaves like a dialog, at once, quicker than it came and speeding off its edge (0.2s, a steady push), fading out.
- Each part leaves its own way unless you set its `exitTransition`: the overlay clears in 250ms, a dialog or a sheet speeds away in 0.2s.
- React Aria only keeps a closing modal mounted if animations are running when it closes, before Motion starts any. Animate UI tracks the same open state React Aria reads (the `DialogTrigger`'s, or `isOpen`/`defaultOpen`) and passes `isExiting` while the exit plays, so `data-exiting` and the `isExiting` render prop stay accurate, focus stops being trapped and returns to the trigger.
- Reopening while it closes picks up from where it is.
- Opening from the keyboard animates the same way; focus moves into the dialog at once.
- `className` and `style` functions keep working, and your own `render` function is made animatable rather than replaced.
- Under reduced motion, the modal fades and un-blurs without tilting, scaling or sliding.
- `AnimateUIProvider tempo` scales every duration and spring.

## API Reference

`Modal` and `ModalOverlay` take exactly the props of [React Aria's Modal](https://react-spectrum.adobe.com/react-aria/Modal.html#props), plus:

### ModalOverlay

<TypeTable
  type={{
    from: {
      description:
        'The edge the modal tips from as it comes in, as in v1. Ignored by a sheet (data-side).',
      type: "'top' | 'bottom' | 'left' | 'right'",
      default: "'top'",
    },
    transition: {
      description:
        'Transition of the fade in (of its background color and backdrop filter).',
      type: 'Transition',
      default: '{ duration: 0.4, ease: [0.25, 0.1, 0.25, 1] }',
    },
    exitTransition: {
      description: 'Transition of the fade out.',
      type: 'Transition',
      default: '{ duration: 0.25, ease: [0.25, 0.1, 0.25, 1] }',
    },
  }}
/>

### Modal

<TypeTable
  type={{
    transition: {
      description:
        'Transition of the opening. One you pass drives its fade too.',
      type: 'Transition',
      default:
        "{ type: 'spring', stiffness: 150, damping: 25, opacity: { duration: 0.4, ease: [0.215, 0.61, 0.355, 1] } }; with data-side: { duration: 0.4, ease: [0.215, 0.61, 0.355, 1] }",
    },
    exitTransition: {
      description: 'Transition of the closing.',
      type: 'Transition',
      default: '{ duration: 0.2, ease: [0.33, 0.17, 0.67, 0.5] }',
    },
  }}
/>

`DialogTrigger`, `Dialog`, `Heading` and the other components take [React Aria props](https://react-spectrum.adobe.com/react-aria/Dialog.html#props) only. They are not animated.
