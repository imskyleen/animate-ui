## Usage

Import from Animate UI instead of `react-aria-components`: it re-exports all of React Aria, with animated `TabList`, `Tab` and `TabPanel`. Everything else stays the same.

```tsx
import {
  Tab,
  TabList,
  TabPanel,
  Tabs,
} from '@animate-ui/react/primitives/react-aria';

export function Settings() {
  return (
    <Tabs>
      <TabList aria-label="Settings">
        <Tab id="account">Account</Tab>
        <Tab id="password">Password</Tab>
      </TabList>
      <TabPanel id="account">Make changes to your account.</TabPanel>
      <TabPanel id="password">Change your password.</TabPanel>
    </Tabs>
  );
}
```

## Animation

- **The selected tab's surface slides** to the new tab on a spring (stiffness 300, damping 30), like Animate UI v1's highlight: the new surface fades in as it slides from the previous one, which follows it and fades out 200ms later. The TabList draws it as an indicator that copies the selected tab's own classes and data attributes, so it looks exactly like your selected tab (background, border, shadow, and the `line` variant's underline) in every style and theme, while the selected tab's own surface is hidden. Its focus ring stays on the tab.
- **The tabs' colors change over 500ms** (`ease`, the curve of a color change), whatever transition your tabs set.
- Clicking quickly through tabs retargets the slide smoothly.
- **The incoming panel fades in from a 4px blur** over 500ms on a strong ease-out, while its height springs from the previous panel's to its own, like v1's tab contents, on the spring of [Auto Height](/docs/primitives/animate-ui/auto-height) and Animate UI's [Tabs](/docs/primitives/animate-ui/tabs) (stiffness 300, damping 30). The panels share an element (the tabs root, usually), which remembers the selected panel's height. The outgoing panel leaves at once, so the two never overlap.
- The selected panel fades in on mount (page load) too, as in v1.
- Keyboard changes animate like clicks, as in v1: arrow keys slide the surface and fade the panel in (with `keyboardActivation="manual"`, Enter selects). The outgoing panel still leaves at once (React Aria would otherwise wait for its fade to end).
- With `shouldForceMount`, inactive panels stay in the DOM and `inert`, as in React Aria, and fade in when they become selected.
- The `className`, `style` and `children` render props keep working. The indicator and the panel go through React Aria's `render` prop; a `render` of your own on `TabList` still receives the indicator, on `TabPanel` it replaces the animation.
- `<AnimateUIProvider tempo>` paces every transition.
- Under reduced motion, the surface jumps and the height changes at once; the fades still play.

## API Reference

Every component takes exactly the props of [React Aria's Tabs](https://react-spectrum.adobe.com/react-aria/Tabs.html#props). Animate UI adds the animation props below.

### Tabs, Tab

[React Aria props](https://react-spectrum.adobe.com/react-aria/Tabs.html#props) only.

### TabList

[React Aria props](https://react-spectrum.adobe.com/react-aria/Tabs.html#tablist), plus:

<TypeTable
  type={{
    transition: {
      description:
        'Transition of the surface sliding to the new tab (pointer changes); the previous surface fades out 200ms after it starts.',
      type: 'Transition',
      default: "{ type: 'spring', stiffness: 300, damping: 30 }",
    },
  }}
/>

### TabPanel

[React Aria props](https://react-spectrum.adobe.com/react-aria/Tabs.html#tabpanel), plus:

<TypeTable
  type={{
    transition: {
      description:
        'Transition of the incoming panel: its fade from a blur, and its height (in `height`, or the whole transition when it has none).',
      type: 'Transition',
      default:
        "{ duration: 0.5, ease: [0.23, 1, 0.32, 1], height: { type: 'spring', stiffness: 300, damping: 30, bounce: 0, restDelta: 0.01 } }",
    },
  }}
/>
