## Usage

Import the primitive from Animate UI instead of Radix UI. Everything else stays the same.

```tsx
import { Menubar } from '@animate-ui/react/primitives/radix-ui';

export function EditorMenubar() {
  return (
    <Menubar.Root>
      <Menubar.Menu>
        <Menubar.Trigger>File</Menubar.Trigger>
        <Menubar.Portal>
          <Menubar.Content align="start" sideOffset={8}>
            <Menubar.Item>New file</Menubar.Item>
            <Menubar.Item>Save</Menubar.Item>
          </Menubar.Content>
        </Menubar.Portal>
      </Menubar.Menu>
      <Menubar.Menu>
        <Menubar.Trigger>Edit</Menubar.Trigger>
        <Menubar.Portal>
          <Menubar.Content align="start" sideOffset={8}>
            <Menubar.Item>Undo</Menubar.Item>
            <Menubar.Item>Redo</Menubar.Item>
          </Menubar.Content>
        </Menubar.Portal>
      </Menubar.Menu>
    </Menubar.Root>
  );
}
```

Coming from the `@radix-ui/react-menubar` package? Use the subpath: `import * as MenubarPrimitive from '@animate-ui/react/primitives/radix-ui/menubar'`.

## Animation

Radix's Menubar has no Animate UI v1 counterpart: each menu moves like v1's Dropdown Menu.

- **Content** fades and scales in from 0.9, from its trigger (`--radix-menubar-content-transform-origin`, set inline so it works without styles), in 250ms (`{ duration: 0.25, ease: [0.215, 0.61, 0.355, 1] }`, a soft ease-out), and closes the same way before it unmounts.
- **SubContent** grows from the side of its trigger the same way.
- Moving from one open menu to another (hovering a trigger or pressing the arrow keys) closes one menu and opens the other, each with its own animation, like any menu.
- **The highlight**: one surface glides behind the highlighted item on a spring (stiffness 500, damping 40), following the pointer and the arrow keys alike, and into submenus. Moving to another item, it carries on from where it is, at its speed: however fast the pointer or the arrow keys go, there's one highlight on screen. It only fades in (200ms) when it appears from nothing. It glides on the compositor (a Web Animation of `transform`), so a busy main thread, a submenu opening for instance, doesn't stall it. Into a submenu or back out of it, each menu clips its own part, as in v1: the previous surface glides along with the new one, the same box on screen, so the two make one highlight crossing from one menu into the other; the entering part fades in as it glides. When the pointer leaves the menu, it stays on the last item. It wears the item's own highlighted background (`focus:bg-accent`, `data-highlighted:bg-accent`…), read from your styles: the item's background is cleared while it's highlighted (or still has the focus, or its submenu is open), and a `focus:` background is read again once the item has the focus; its text colors stay.
- **ItemIndicator**: a checkbox item's check draws itself like a Checkbox's check (its stroke and opacity in 0.3s on Motion's easeOut, at once: there's no box to fill first) whenever it appears (checking the item, or opening the menu), and erases itself in 0.3s when the item is unchecked (it stays mounted for that). A radio item's check glides to the newly checked item on the highlight's spring, like a select's.
- Choosing an item closes the menu (Radix's default): when its check moves (a radio item's glides from the one shown, a checkbox item's draws or erases itself), the menu holds still for 150ms first, so the change is seen, then fades out. Escape and outside clicks don't wait.
- When the menu closes with focus inside, focus goes back to the menu's trigger at once instead of after the exit, and the leaving menu ignores the pointer and can't dismiss anything.
- With `forceMount` (on the Content or the Portal), the closed content stays in the DOM: it plays its exit, then is hidden (`visibility: hidden`).
- A menu open from the start (the Root's `defaultValue`) plays its entrance on page load, like v1's menus.
- Under reduced motion, nothing scales or glides: the menu and the checks only fade, and the menu doesn't hold; the highlight jumps from item to item and only fades in when it appears.

## API Reference

Every part takes exactly the props of [Radix UI's Menubar](https://www.radix-ui.com/primitives/docs/components/menubar#api-reference). Animate UI adds the animation props below.

### Root, Menu, Trigger, Portal, Group, Label, RadioGroup, Separator, Arrow, Sub

[Radix UI props](https://www.radix-ui.com/primitives/docs/components/menubar#api-reference) only. They are not animated.

### Item, CheckboxItem, RadioItem, SubTrigger

[Radix UI props](https://www.radix-ui.com/primitives/docs/components/menubar#item) only. They take part in the highlight; it needs nothing more.

### Content, SubContent

[Radix UI props](https://www.radix-ui.com/primitives/docs/components/menubar#content), plus:

<TypeTable
  type={{

[Radix UI props](https://www.radix-ui.com/primitives/docs/components/menubar#itemindicator), plus:
