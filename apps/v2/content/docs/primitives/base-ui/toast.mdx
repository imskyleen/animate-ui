## Usage

Import the primitive from Animate UI instead of Base UI. Everything else stays the same.

```tsx
import { Toast } from '@animate-ui/react/primitives/base-ui/toast';

function ToastList() {
  const { toasts } = Toast.useToastManager();
  return toasts.map((toast) => (
    <Toast.Root key={toast.id} toast={toast}>
      <Toast.Content>
        <Toast.Title />
        <Toast.Description />
        <Toast.Close aria-label="Close">×</Toast.Close>
      </Toast.Content>
    </Toast.Root>
  ));
}

export function Toaster({ children }: { children: React.ReactNode }) {
  return (
    <Toast.Provider>
      {children}
      <Toast.Portal>
        <Toast.Viewport>
          <ToastList />
        </Toast.Viewport>
      </Toast.Portal>
    </Toast.Provider>
  );
}
```

## Animation

Base UI drives the stack, swipe-to-dismiss and the enter/exit itself, through CSS variables and its transition status, and waits for CSS transitions before removing a toast. So the Root animates with CSS transitions too (a JavaScript animation would fight the swipe), but writes them itself from its state and Animate UI's tokens, so `AnimateUIProvider tempo` applies.

- **A toast enters from its edge**, a full toast height away, and fades in over 600ms with a strong ease-out.
- **Stack**: collapsed, each toast behind the front one scales down by 0.05 per step (never below 0.9) and peeks out by 0.75rem; its content fades out (`data-behind`). Hovering or focusing the viewport expands the stack with a 0.75rem gap. Toasts added quickly retarget instead of restarting.
- **A swipe follows the finger** (Base UI sets the transform while swiping), then springs back, or the toast leaves in the swipe direction.
- **It exits faster** (400ms) through the edge it came from.
- Toasts swiped up (`swipeDirection="up"`) live at the top edge: they enter and leave through it. Anchored toasts (`Toast.Positioner`) grow from their anchor instead.
- shadcn/ui's own CSS stack (its `[transform:…]` and `[transition:…]` classes and the variables only they read) would fight these: the CLI removes them.
- Under reduced motion, toasts fade in place and the stack changes at once.

## API Reference

Every part takes exactly the props of [Base UI's Toast](https://base-ui.com/react/components/toast#api-reference). Animate UI adds the animation props below. They are CSS transitions: their `duration` and cubic-bezier `ease` are used.

### Provider, Viewport, Portal, Positioner, Title, Description, Action, Close, Arrow

[Base UI props](https://base-ui.com/react/components/toast#provider) only.

### Root

[Base UI props](https://base-ui.com/react/components/toast#root), plus:

<TypeTable
  type={{
    transition: {
      description: 'Transition of the entrance and the stack.',
      type: 'Transition',
      default: 'transition.dropdown (600ms, ease-out)',
    },
    exitTransition: {
      description: 'Transition of the exit.',
      type: 'Transition',
      default: 'transition.exit (400ms, ease-out)',
    },
  }}
/>

The Root sets its `transform`, `transition` and `opacity` through Base UI's `style` prop; a `style` of your own (object or function) still applies on top.

### Content

[Base UI props](https://base-ui.com/react/components/toast#content), plus:

      type: 'Transition',
      default: 'transition.fade (600ms, ease-out)',
    },
  }}
/>
