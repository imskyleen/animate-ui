## Usage

Import the primitive from Animate UI instead of Base UI. Everything else stays the same.

```tsx
import { Toast } from '@animate-ui/react/primitives/base-ui/toast';

function ToastList() {
  const { toasts } = Toast.useToastManager();
  return toasts.map((toast) => (
    <Toast.Root key={toast.id} toast={toast}>
      <Toast.Content>
        <Toast.Title />
        <Toast.Description />
        <Toast.Close aria-label="Close">×</Toast.Close>
      </Toast.Content>
    </Toast.Root>
  ));
}

export function Toaster({ children }: { children: React.ReactNode }) {
  return (
    <Toast.Provider>
      {children}
      <Toast.Portal>
        <Toast.Viewport>
          <ToastList />
        </Toast.Viewport>
      </Toast.Portal>
    </Toast.Provider>
  );
}
```

Using the `@base-ui/react` umbrella import instead? The barrel mirrors it: `import { Toast } from '@animate-ui/react/primitives/base-ui'`.

## Animation

Animate UI v1 had no toast. Its motion comes from v1's Sheet (it enters and leaves through its edge with a fade, on v1's sheet spring: stiffness 150, damping 22), a tooltip's motion for anchored toasts, and a 200ms ease-out fade.

Base UI drives the stack, swipe-to-dismiss and the enter/exit itself, through CSS variables and its transition status, and waits for CSS transitions before removing a toast. So the Root animates with CSS transitions too (a JavaScript animation would fight the swipe), springs written as the `linear()` curve Motion itself would use (550ms for the sheet spring), and sets them itself from its state, so `AnimateUIProvider tempo` applies.

- **A toast enters from its edge**, a full toast height away, sliding and fading in on the spring.
- **Stack**: collapsed, each toast behind the front one scales down by 0.05 per step (never below 0.9) and peeks out by 0.75rem; its content fades out (`data-behind`) in 200ms, ease-out. Hovering or focusing the viewport expands the stack with a 0.75rem gap and fades the contents back in. The stack moves on the same spring, and toasts added quickly retarget instead of restarting.
- **A swipe follows the finger** (Base UI sets the transform while swiping), then springs back, or the toast leaves in the swipe direction.
- **It leaves through the edge it came from**, sliding and fading out on the same spring.
- Toasts swiped up (`swipeDirection="up"`) live at the top edge: they enter and leave through it. Anchored toasts (`Toast.Positioner`) are small bubbles, like tooltips: they grow from their anchor from 0.7 with a fade, on a spring (stiffness 400, damping 29).
- shadcn/ui's own CSS stack (its `[transform:…]` and `[transition:…]` classes and the variables only they read) would fight these: the CLI removes them.
- Under reduced motion, toasts fade in place and the stack changes at once.

## API Reference

Every part takes exactly the props of [Base UI's Toast](https://base-ui.com/react/components/toast#api-reference). Animate UI adds the animation props below. They are CSS transitions: a spring becomes a `linear()` curve, a tween keeps its `duration` and cubic-bezier or named `ease`.

### Provider, Viewport, Portal, Positioner, Title, Description, Action, Close, Arrow

[Base UI props](https://base-ui.com/react/components/toast#provider) only.

### Root

[Base UI props](https://base-ui.com/react/components/toast#root), plus:

<TypeTable
  type={{
    transition: {
      description: 'Transition of the entrance and the stack.',
      type: 'Transition',
      default:
        "{ type: 'spring', stiffness: 150, damping: 22 }; anchored: { type: 'spring', stiffness: 400, damping: 29 }",
    },
    exitTransition: {
      description: 'Transition of the exit.',
      type: 'Transition',
      default: 'transition',
    },
  }}
/>

The Root sets its `transform`, transition and `opacity` through Base UI's `style` prop; a `style` of your own (object or function) still applies on top.
