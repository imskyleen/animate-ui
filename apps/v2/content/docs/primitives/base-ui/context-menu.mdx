## Usage

Import the primitive from Animate UI instead of Base UI. Everything else stays the same.

```tsx
import { ContextMenu } from '@animate-ui/react/primitives/base-ui/context-menu';

export function CanvasMenu() {
  return (
    <ContextMenu.Root>
      <ContextMenu.Trigger>Right click here</ContextMenu.Trigger>
      <ContextMenu.Portal>
        <ContextMenu.Positioner>
          <ContextMenu.Popup>
            <ContextMenu.Item>Undo</ContextMenu.Item>
            <ContextMenu.Item>Duplicate</ContextMenu.Item>
            <ContextMenu.Separator />
            <ContextMenu.Item>Delete</ContextMenu.Item>
          </ContextMenu.Popup>
        </ContextMenu.Positioner>
      </ContextMenu.Portal>
    </ContextMenu.Root>
  );
}
```

Using the `@base-ui/react` umbrella import instead? The barrel mirrors it: `import { ContextMenu } from '@animate-ui/react/primitives/base-ui'`.

## Animation

Base UI's Context Menu has no Animate UI v1 counterpart: it moves like v1's Base UI Menu.

- **Popup** fades and scales in from 0.9, from the pointer (`--transform-origin`, set inline so it works without styles), in 250ms (`{ duration: 0.25, ease: [0.215, 0.61, 0.355, 1] }`, a soft ease-out), and closes the same way. Submenu popups grow from the side of their trigger the same way.
- Base UI keeps the popup mounted after it closes, and Animate UI unmounts it once the exit has played (`onOpenChangeComplete` fires then).
- **The highlight**: one surface glides behind the highlighted item on a spring (stiffness 500, damping 40), following the pointer and the arrow keys alike, and into submenus. Moving to another item, it carries on from where it is, at its speed: however fast the pointer or the arrow keys go, there's one highlight on screen. It only fades in (200ms) when it appears from nothing. It glides on the compositor (a Web Animation of `transform`), so a busy main thread, a submenu opening for instance, doesn't stall it. Into a submenu or back out of it, the submenu clips the surface gliding in from its trigger: the trigger's surface stays and fades out as the new one shows, so the highlight never drops out. When the pointer leaves the menu, it stays on the last item. It wears the item's own highlighted background (`focus:bg-accent`, `data-highlighted:bg-accent`…), read from your styles: the item's background is cleared while it's highlighted (or still has the focus, or its submenu is open), and a `focus:` background is read again once the item has the focus; its text colors stay.
- **CheckboxItemIndicator** pops in from half its size out of a light blur (2px), with a little overshoot, whenever it appears (checking the item, or opening the menu), and shrinks back into its blur in 150ms when the item is unchecked (Animate UI keeps it mounted for that). **RadioItemIndicator** glides to the newly checked item on the highlight's spring, like a select's check.
- With `closeOnClick` on an item, choosing it closes the menu: when its check moves (a radio item's glides from the one shown, a checkbox item's pops in or out), the menu holds still for 150ms first, so the change is seen. Escape and outside clicks don't wait.
- When the menu closes with focus inside, focus goes back to where it was before the menu opened at once instead of after the exit, and the leaving popup ignores the pointer.
- With `keepMounted` on the Portal, the closed popup stays in the DOM and Base UI hides it after the exit.
- Open from the start (`defaultOpen`), the menu plays its entrance on page load.
- Under reduced motion, nothing scales or glides: the menu and the checks only fade, and the menu doesn't hold; the highlight jumps from item to item and only fades in when it appears.

## API Reference

Every part takes exactly the props of [Base UI's Context Menu](https://base-ui.com/react/components/context-menu#api-reference). Animate UI adds the animation props below. The Popup's `render` prop is used by the animation.

### Root, Trigger, Portal, Positioner, Group, GroupLabel, RadioGroup, SubmenuRoot, Separator, Arrow, Backdrop

[Base UI props](https://base-ui.com/react/components/context-menu#api-reference) only. They are not animated.

### Item, LinkItem, CheckboxItem, RadioItem, SubmenuTrigger

[Base UI props](https://base-ui.com/react/components/context-menu#api-reference) only. They take part in the highlight; it needs nothing more.

### Popup

[Base UI props](https://base-ui.com/react/components/context-menu#popup), plus:

<TypeTable
  type={{

[Base UI props](https://base-ui.com/react/components/context-menu#checkbox-item-indicator), plus:
