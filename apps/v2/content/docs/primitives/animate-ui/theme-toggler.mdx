## Usage

Bring your own theme state: `ThemeToggler` takes the theme and its setter as props, so it works with any theme library. With [next-themes](https://github.com/pacocoursey/next-themes):

```tsx
import { useTheme } from 'next-themes';
import {
  ThemeToggler,
  type Resolved,
  type ThemeSelection,
} from '@animate-ui/react/primitives/effects/theme-toggler';

export function ThemeButton() {
  const { theme, resolvedTheme, setTheme } = useTheme();

  return (
    <ThemeToggler
      theme={theme as ThemeSelection}
      resolvedTheme={resolvedTheme as Resolved}
      setTheme={setTheme}
    >
      {({ effective, toggleTheme }) => (
        <button
          onClick={() => toggleTheme(effective === 'dark' ? 'light' : 'dark')}
        >
          {effective === 'dark' ? 'Light mode' : 'Dark mode'}
        </button>
      )}
    </ThemeToggler>
  );
}
```

During the wipe, the `dark` class is toggled on `<html>`: this matches class-based dark mode (Tailwind's default, next-themes with `attribute="class"`).

## Animation

- The new theme is revealed with a clip-path wipe over 700ms with an `ease-in-out`, in `direction` (left to right by default). The old and new pages are snapshots, so nothing re-renders mid-wipe.
- `setTheme` is called once the wipe finishes; `onImmediateChange` fires right away.
- Switching to `system` when it resolves to the current theme changes nothing on screen, so there is no wipe.
- Browsers without the View Transitions API swap the theme at once.
- `<AnimateUIProvider tempo>` paces the wipe.
- Under reduced motion, the theme swaps at once, without the wipe.
- On the server and while hydrating, the render function receives `effective: 'system'` and `resolved: 'light'`, since the theme is only known on the client.
