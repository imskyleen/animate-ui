## Usage

```tsx
import {
  Tabs,
  TabsContent,
  TabsContents,
  TabsHighlight,
  TabsHighlightItem,
  TabsList,
  TabsTrigger,
} from '@animate-ui/react/primitives/tabs';

export function Settings() {
  return (
    <Tabs defaultValue="account">
      <TabsHighlight className="absolute inset-0 rounded-md bg-background">
        <TabsList className="flex rounded-lg bg-muted p-1">
          <TabsHighlightItem value="account" className="flex-1">
            <TabsTrigger value="account">Account</TabsTrigger>
          </TabsHighlightItem>
          <TabsHighlightItem value="password" className="flex-1">
            <TabsTrigger value="password">Password</TabsTrigger>
          </TabsHighlightItem>
        </TabsList>
      </TabsHighlight>
      <TabsContents>
        <TabsContent value="account">
          Make changes to your account here.
        </TabsContent>
        <TabsContent value="password">Change your password here.</TabsContent>
      </TabsContents>
    </Tabs>
  );
}
```

Unlike the library tabs, these are Animate UI's own: no Radix UI, Base UI or React Aria underneath. `TabsHighlight` and `TabsHighlightItem` are optional; without them, style the active trigger with `data-state="active"`. `TabsHighlight`'s classes style the highlight, which the `TabsList` inside draws behind the selected trigger's `TabsHighlightItem`. Without `defaultValue`, the first trigger is selected.

## Animation

They move like the [library tabs](/docs/primitives/radix-ui/tabs), after Motion's tabs example:

- **One highlight slides** to the selected trigger on a spring (stiffness 300, damping 30). Clicking quickly or holding an arrow key retargets it from where it is, at the speed it has. It moves on the compositor (a Web Animation of its `translate`, and of its size when the triggers' sizes differ), so the panels changing never hold it up.
- **The panels change one after the other**, like Motion's `AnimatePresence` with `mode="wait"`: the outgoing panel fades out into a 5px blur over 150ms on an ease-out, staying in the page and out of reach (`inert`); once it's gone, the incoming one fades in from the blur over 300ms while its height glides from the outgoing panel's to its own, over 450ms on Motion's layout curve (a gentle start, then a long deceleration, never past its size). `TabsContents` follows it: its border and background glide with it. Inactive panels stay mounted, `hidden` and `inert`.
- **A panel's box stays on screen.** When the panels hold a box (a Card: the panel itself if it draws a border, a background or a shadow, else the first element down its chain of single children that does), only what's inside it fades, like Motion's example where the bordered box stays: the next panel's box takes over at the same height in the same frame, then glides to its own height, clipping its content but never its own border or corners, so the border never blinks or gets cut. Boxes that don't look the same (border, radius, background, shadow), or that hold text right inside, fade whole. Content positioned against something outside what fades (a step's badge on its rail) fades without the blur, so it stays in place.
- Changing tabs again before that's over stays clean: a panel passed over before it showed never shows, one coming in fades back out from where it is, one picked again while it leaves comes back from there, and the height goes on from where it is. Two panels never show at once.
- Nothing animates on page load (nor a value restored before the page is painted).
- The triggers' colors are yours: the demo's change over 200ms (`ease`), like the library tabs'.
- Keyboard: arrow keys move to the next or previous enabled trigger (wrapping) and select it, Home and End jump to the ends; only the selected trigger is in the Tab order. Keyboard selection animates exactly like a click.
- `<AnimateUIProvider tempo>` paces every transition.
- Under reduced motion, the highlight and the height jump; the panels still change one after the other, fading only (no blur), the incoming one over 200ms.
