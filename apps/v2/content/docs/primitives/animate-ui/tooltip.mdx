## Installation

<Installation />

The popup is positioned with [Floating UI](https://floating-ui.com), a peer dependency of this primitive:

```bash
npm install @floating-ui/react
```

## Usage

```tsx
import {
  Tooltip,
  TooltipArrow,
  TooltipContent,
  TooltipProvider,
  TooltipTrigger,
} from '@animate-ui/react/primitives/tooltip';

export function Toolbar() {
  return (
    <TooltipProvider>
      <Tooltip>
        <TooltipTrigger asChild>
          <button aria-label="Bold">B</button>
        </TooltipTrigger>
        <TooltipContent className="rounded-md bg-foreground px-3 py-1.5 text-xs text-background">
          <TooltipArrow className="size-2.5 fill-foreground" />
          <p>Bold</p>
        </TooltipContent>
      </Tooltip>

      <Tooltip side="bottom">
        <TooltipTrigger asChild>
          <button aria-label="Italic">I</button>
        </TooltipTrigger>
        <TooltipContent className="rounded-md bg-foreground px-3 py-1.5 text-xs text-background">
          <TooltipArrow className="size-2.5 fill-foreground" />
          <p>Italic</p>
        </TooltipContent>
      </Tooltip>
    </TooltipProvider>
  );
}
```

Unlike the library tooltips, this one is Animate UI's own: no Radix UI, Base UI or React Aria underneath. `TooltipContent` renders nothing where it is written: it declares what the provider's single popup shows when its trigger is hovered or focused. Put a `motion` element with `layout="preserve-aspect"` around the text to keep it from stretching while the popup resizes between triggers.

## Animation

The motion of Animate UI v1's Tooltip, on the spring of the library tooltips and popovers:

- The popup grows from nothing and rises 15px out of its trigger (from the side it's placed on) as it fades in, on a spring (stiffness 300, damping 25) that takes it about 4% past full size before it settles, and goes back the same way when it closes.
- Hovering the next trigger while a tooltip is showing doesn't close it: the popup and its arrow glide to the new trigger and resize to the new content (a shared layout animation), on the same spring. Right after a tooltip closes (within `closeDelay`), the next one opens without the `openDelay`.
- `<AnimateUIProvider tempo>` paces the spring.
- Under reduced motion, the popup only fades, and moving between triggers jumps.

## API Reference

### TooltipProvider

Holds the shared popup. Every `Tooltip` must be inside one.

<TypeTable
  type={{
    children: {
      description: 'The tooltips.',
      type: 'React.ReactNode',
      required: true,
    },
    id: {
      description:
        'Identifies the shared popup (its layout id). Defaults to a generated id.',
      type: 'string',
    },
    openDelay: {
      description: 'Delay in milliseconds before a tooltip opens.',
      type: 'number',
      default: '0',
    },
    closeDelay: {
      description:
        'Delay in milliseconds before a tooltip closes. A tooltip opened within this window after one closed opens at once.',
      type: 'number',
      default: '300',
    },
    transition: {
      description:
        'Transition of the entrance, of the exit and of the move between triggers.',
      type: 'Transition',
      default: "{ type: 'spring', stiffness: 300, damping: 25 }",
    },
  }}
/>

### TooltipTrigger

Opens the tooltip on hover and focus, and closes it on leave, blur, a press, <kbd>Escape</kbd>, scroll and resize. While open, it gets `aria-describedby` pointing at the popup (`role="tooltip"`).

### useGlobalTooltip, useTooltip

Return the provider's and the tooltip's state: the current tooltip, `showTooltip`, `hideTooltip` and `hideImmediate`; the tooltip's side, alignment and id.
